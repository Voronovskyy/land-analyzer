# Науково-технічний звіт

## Інтелектуальна ГІС-система комплексного аналізу та оцінки земельних ділянок

**Виконавець:** Вороновський Данило 
**Науковий керівник:** кафедра комп'ютерних наук  
**Установа:** Лісотехнічний університет України  
**Дата:** 25.04.2026

---

## 1. Постановка задачі

Традиційна оцінка земельних ділянок вимагає ручного збору даних із кількох незалежних джерел:
кадастрових реєстрів, метеорологічних баз, супутникових знімків, даних OpenStreetMap та ін.
Цей процес займає від кількох годин до кількох днів і залежить від кваліфікації виконавця.

**Задача:** розробити настільну ГІС-систему, яка автоматизує весь цикл аналізу — від введення
адреси чи кадастрового номера до готового PDF-звіту — і доповнює кількісні показники
якісними висновками великої мовної моделі (LLM).

---

## 2. Реалізована система

### 2.1 Загальні характеристики

- **Платформа:** JavaFX 17 (desktop, Windows/Linux/macOS)
- **Інтерфейс карти:** Leaflet.js у WebView (6 картографічних шарів)
- **AI-модуль:** Claude API (Anthropic) — 6 незалежних ролей аналізу
- **Вихідний документ:** PDF, 6–8 сторінок (OpenPDF + кирилиця Arial)
- **Зовнішні API:** 10 джерел даних (без платних ключів, крім Claude)

### 2.2 Джерела даних

| Джерело | Дані | Використання |
|---------|------|--------------|
| Open-Meteo | Клімат 30 д. + місячний архів | Графік погоди, агрокліматика |
| Open-Elevation | Висота над рівнем моря | Рельєф, ризик підтоплення, схили |
| OSM Overpass | Дороги, ЛЕП, водойми, POI | Інфраструктурний паспорт |
| Nominatim | Геокодування адрес | Пошук ділянки за адресою |
| DOM.RIA | Ринкова ціна м² | Ринкова оцінка вартості |
| НБУ / ПриватБанк | Курс USD/UAH | Конвертація вартості |
| Esri / OSM tiles | Картографічні шари | Супутник, рельєф, DEM, NDVI |
| ДЗК (mock) | Кадастрові межі | Пошук за кадастровим номером |

### 2.3 Аналітичні модулі

**Площа та геометрія**
Полігон ділянки обчислюється формулою Shoelace (реалізація JTS). Вхідні дані —
межі з кадастру (GeoJSON) або точки, введені вручну.

**Оцінка вартості**
Базова: площа × ставка НГО (грн/м²) з `application.properties`.
Ринкова: середня ціна м² за DOM.RIA у радіусі локації, запит асинхронний.

**Індекс придатності**
Зважена сума трьох факторів: висота над рівнем моря (рельєф), наявність
інфраструктури (дороги, ЛЕП), кліматичні показники (температура, опади).

**Агрокліматика**
Індекс аридності Де Мартонна: `I = P / (T̄ + 10)`.
Класифікація: посушливий → напівпосушливий → напівгумідний → гумідний → гіпергумідний.

**Ризик підтоплення**
Визначається за абсолютною висотою: < 50 м — високий ризик (низовина),
50–100 м — підвищений, 100–200 м — помірний, > 200 м — низький/мінімальний.

**Схили**
Кут ухилу оцінюється через перепад висот кутів ділянки (Elevation API) та
довжину діагоналі полігону (формула Haversine).

### 2.4 AI-аналіз (Claude)

Для кожного картографічного шару система виконує незалежний запит до Claude API
з промтом конкретної ролі:

| Шар | Роль | Фокус аналізу |
|-----|------|---------------|
| Схема інфраструктури | Містобудівний аналітик | Транспортна доступність, інженерні мережі |
| Топографічний рельєф | Геоморфолог | Рельєфні умови будівництва |
| DEM | Гідролог | Ризики підтоплення, дренаж |
| NDVI | Агроеколог | Стан рослинності, придатність для агро |
| Супутниковий знімок | Інвестиційний аналітик | Потенціал розвитку, інфраструктурне оточення |
| Карта схилів | Інженер-геодезист | Ухили, ерозійний ризик, будівельні обмеження |

Промти зберігаються у `src/main/resources/prompts/*.md` — редагуються без перекомпіляції.

## 3. Архітектурні рішення

### 3.1 Асинхронна 3-фазна генерація звіту

```
Phase 1: collectApiData      — паралельні HTTP-запити (CompletableFuture.supplyAsync)
Phase 2: captureMapLayers    — послідовні знімки WebView (CountDownLatch per layer)
Phase 3: assemblePdf         — Platform.runLater → PdfReportService
```

Паралелізм у фазі 1 скорочує час збору даних з ~60 с (послідовно) до ~15 с.
`CountDownLatch` у фазі 2 гарантує, що тайли Leaflet завантажені перед знімком.

### 3.2 Надійність Elevation API

Запит висоти виконується до 5 разів із паузою 3 секунди між спробами.
Це покриває тимчасові збої публічного Open-Elevation API без зупинки конвеєру.

### 3.3 Управління промтами поза кодом

`PromptLoader` читає MD-файли з classpath і кешує у `ConcurrentHashMap`.
Редагування ролі або тексту задачі не вимагає перекомпіляції — достатньо
перезапустити додаток.

### 3.4 Модульний PDF

`PdfReportService` делегує примітиви стилів у `PdfCellHelper` (import static)
і конструкцію таблиць карт у `MapExtrasBuilder` (import static).
Це скоротило основний файл з ~1100 до ~700 рядків та ізолювало зміни стилів.

## 4. Науковий внесок

1. **Інтеграція LLM у ГІС-конвеєр** — поєднання кількісних геопросторових метрик
   (площа, висота, NDVI, клімат) з якісним AI-аналізом у єдиному документі.

2. **Автоматизація повного циклу оцінки** — від координати до підписаного PDF
   за одне натискання кнопки, без ручного збору даних.

3. **Верифікована мультиджерельність** — 10 незалежних API перехресно перевіряють
   одні й ті ж характеристики ділянки (висота, клімат, інфраструктура).

4. **Відтворюваність** — кожен звіт містить метадані джерел; результати
   відтворювані для тих самих координат і дати запиту.

## 5. Обмеження та напрями розвитку

| Обмеження | Причина | Плановий розвиток |
|-----------|---------|-------------------|
| Кадастровий пошук — mock | API ДЗК потребує авторизації | Інтеграція з публічним API ДЗК |
| NDVI — тайловий шар | Немає чисельного NDVI-значення | Підключення Sentinel Hub API |
| Ринкова ціна — лише DOM.RIA | Одне джерело | Агрегація OLX, ЛУН, Rieltor.ua |
| Claude API — платний | Anthropic pricing | Можливість перемикання на локальну LLM |
